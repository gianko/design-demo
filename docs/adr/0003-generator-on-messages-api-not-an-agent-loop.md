# The generator is two Messages API calls, not an agent loop

Screens are generated by a fixed two-step workflow on the Messages API: `messages.parse()` with a Zod schema turns a screen brief into a UI spec, and a second call turns that UI spec into TSX, with gates run locally between and after them. The model never chooses a tool or explores files, so an agent harness gives it nothing to use. The gates, repair policy and eval accounting are ours whichever runtime runs them, so the direct API is the least code (~100–150 lines, `@anthropic-ai/sdk` and `zod` only) and the most repeatable: we own the exact system prompt, parameters and transcript. This narrows demo brief §3's "reuse the agent-quiz-app pattern": the design system is still built by the unattended, issue-tracked Claude Code build loop, but one rep of a screen brief in an eval run isn't an issue, so the generator keeps "unattended" and "spec-first" and drops "issue-tracked". Findings are in [Research agent runtime options](https://github.com/gianko/design-demo/issues/5).

## Decisions that come with it

- **API key, not the subscription.** The Messages API can't authenticate with a claude.ai subscription. The key lives in a gitignored `.env`, with a Console spend limit (~$50/month) as the hard backstop. Eval runs don't draw on the subscription the build loop needs.
- **`claude-opus-5-5` for both steps**, effort `medium` for the spec step and `high` for the code step, set explicitly (Opus 5.5 can't disable thinking). Model and effort sit in one per-step config so an eval comparison can vary them like prompt and registry versions.
- **Zod**, through `zodOutputFormat()`, which converts the schema for the request and validates and parses the response. ArkType has no helper, and its responses would go unvalidated.
- **The wire schema is flat.** Structured outputs reject recursive schemas and cap a request at 24 optional and 16 union-typed parameters, so the UI spec sent to the API is a flat node list. The exact per-component prop check lives in the registry gate (gate 1), run locally. Both schemas are shaped in [Decide UI spec schema and registry generation](https://github.com/gianko/design-demo/issues/11).
- **Repair turns are append-only.** A failing step's response goes back onto its own `messages` array unchanged, followed by a user turn listing the gate failures. Earlier turns are never edited, as preserved thinking requires.
- **The code step sees the UI spec and the screen brief.** The UI spec is what the code must follow; the screen brief rides along as context for intent, copy and motion, so a code-step repair still has the original screen brief.
- **Cost is computed, not estimated.** Each attempt logs its `usage`, priced from a table checked into the repo. The design brief and registry form a cached `system` prefix shared across reps.
- **A `tsx` CLI** that the eval runner calls directly.

## Considered options

- **Claude Agent SDK**: has structured output, follow-up turns, cost fields and unattended mode, but saves no code, adds a bundled Claude Code binary and settings it loads from disk that must be switched off, and reports costs the docs call "client-side estimates".
- **The agent-quiz-app Ralph loop as-is**: picks one GitHub issue, implements it and closes it. It has no schema-constrained output, gate failures reach it only through git log and issue text, and it discards cost data. Right for the build loop, wrong for the generator.
- **Headless Claude Code (`claude -p`) on the subscription**: no per-token bill, but `--bare` turns off subscription login, so isolating runs from the repo's settings rests on untested flags. Schema output is validate-and-re-prompt, not constrained. It's undocumented whether `--resume` combines with `--json-schema`. Costs are estimates. Eval runs would share 5-hour and weekly limits with the build loop and could stop partway.
- **Both, behind one model-client interface**: about 50 more lines and two behaviours to keep matched, for a saving P0 doesn't need. Cheap to add later if spend becomes a problem.
- **Adding tools to the code step**: deferred. If it later needs them (e.g. looking up component docs), the SDK tool runner fits in without changing the shape.
